# Webview with fast-scroll deferral (E35.8)

Measured 2026-10-30 on Windows with `node scripts/bench/webview.mjs` on branch
`E35.8-settled-scroll` (on `main` at `683bb2f`). Release build
(`pnpm tauri build --no-bundle`), same machine and library as
[webview-2026-10-30-after-e35.md](webview-2026-10-30-after-e35.md): Ryzen 9
3900X, 64 GB, 2560×1440 at 60 Hz, `D:\private\fm-reference-library` (15,329
faces in 2,544 families). Default settings of the script (60 s settle, 5 s per
scroll run), warm start, one run. Raw report: `target/bench/webview-e358.json`
(not committed).

What changed: while a view moves faster than one row per frame (two frames in a
row), List, Grid and Waterfall start no face loads, sample-text, size-factor,
metrics, family or thumbnail requests; a row shows its name in the UI font, a
card its empty frame. 100 ms after the position rests within one row, the rows
on screen load (`apps/desktop/src/list/settle.ts`).

in List drag, Table and Waterfall.
