# List faces from an `ArrayBuffer`: no memory gain (E35.6)

Measured 2026-10-30 on Windows with `scripts/bench/webview.mjs`, same machine,
library and settings as `webview-2026-10-29.md` (15,329 faces in 2,544
families, every optional feature on, warm start, release build). One run per
row. "Branch" is E35.6: `faceLoader.ts` fetches each face's file into an
`ArrayBuffer` and makes the `FontFace` from it. "Base" is the same build with
the loader's `url("fmfont:…")` source (the `bytes` deps left out of
`useFaceLoader`), so only the face source differs. `--modes List` is new in
this story: it scrolls the List alone.

## Verdict

The buffer route does **not** bring the number down (criterion 4 applies:
the story stops here and reports). After the List alone, both builds idle
back under 700 MB; after all four views, the branch keeps slightly *more*
than the base, and the List's fast-scroll frames are worse.

## List alone (`--modes List`), private working set (MB)

| Sample | Base: webview | Branch: webview | Base: total | Branch: total |
|--------|-------------:|---------------:|-----------:|-------------:|
| Idle, 60 s after start | 133 | 134 | 195 | 196 |
| After scrolling List | 732 | 888 | 814 | 968 |
| Idle again, 60 s (`idle_after`) | **565** | **576** | 635 | 638 |

The criterion's number (webview in `idle_after` under 700 MB) holds on the
branch, **and it already held without the change**: the renderer gives the
font data of dropped faces back within 60 s when the List is the only view
scrolled. 565–576 MB is the floor the E35.1 forced collection found (567 MB).

## All four views (the E35.1 run), private working set (MB)

| Sample | Base: webview | Branch: webview | Base: JS heap | Branch: JS heap |
|--------|-------------:|---------------:|-------------:|---------------:|
| Idle | 135 | 134 | 18 | 18 |
| After List | 1,336 | 957 | 35 | 123 |
| After Table | 894 | 921 | 43 | 47 |
| After Grid | 1,967 | 2,296 | 941 | 1,082 |
| After Waterfall | 2,458 | 2,934 | 994 | 1,496 |
| Idle again, 60 s | **1,765** | **1,853** | 976 | 964 |

The 1.6–1.8 GB that stays after the full run is not the List's fonts: the
base drops from 1,336 to 894 MB while the Table scrolls (no faces per row),
and the JS heap jumps by about 900 MB in the Grid and stays there. That is
cost 2 of `webview-2026-10-29.md` (the thumbnail map and its IPC byte arrays,
`src/stores/thumbnails.ts`), not the font loader.

## Frames, List, 5 s per pace

| Pace | Base: >18 ms | Branch: >18 ms | Base: >50 ms | Branch: >50 ms | Base: p95 | Branch: p95 |
|------|------------:|--------------:|------------:|--------------:|---------:|-----------:|
| wheel (List-only run) | 0 % | 0 % | 0 | 0 | 16.8 | 16.8 |
| fling (List-only run) | 45.8 % | 69.6 % | 11 | 35 | 66.1 | 116.8 |
| drag (List-only run) | 37.9 % | 47.6 % | 26 | 41 | 83.6 | 83.5 |
| wheel (full run) | 0 % | 0 % | 0 | 0 | 16.8 | 16.8 |
| fling (full run) | 50.8 % | 70.9 % | 14 | 32 | 66.7 | 133.5 |
| drag (full run) | 42.4 % | 64.6 % | 26 | 47 | 83.4 | 100.2 |

Wheel pace stays at 60 fps on both. At fling and drag pace the branch misses
more frames: each face now costs a `fetch`, a copy into the JS heap and a
parse from the buffer before the row can paint.

## What this means for E35.3

- The retained font data E35.1 blamed on `FontFace` url sources is released
  by the renderer on its own once the List stops (565 MB after 60 s idle,
  the browser caches' floor). Making the bytes visible to the collector
  changes nothing measurable.
- The memory that stays after use is the Grid's thumbnails in the JS heap
  (about 900 MB), a frontend fix.
- Shipping the buffer loader would cost fast-scroll frames for no memory.
  A human decides whether to drop it (recommended) or keep it.
