# E27.8 — MCP end-to-end test, 2026-10-31

The installed app (`fm-app.exe` 0.1.0, API 0.23.0, built from `main` on 2026-10-29) on
Windows 11, the user's own library (`H:\Fonts New`, 1,137 faces). MCP turned on in
Settings → AI assistants. Tokens and ports are redacted. The raw transcripts are in
`target/bench/mcp-*.txt` on the test machine (not committed; they hold no token either).

## 2. The stdio shim (what Claude Desktop starts)

A small JSON-RPC client started `fm-mcp-stdio.exe` from the install folder and spoke MCP
to it over stdin/stdout, the way Claude Desktop does.

```
--- initialize
serverInfo: { "name": "font-manager", "version": "0.23.0" }
capabilities: prompts, resources, tools

--- tools/list: 17 tools
search_fonts, get_font, list_collections, list_sets, check_coverage, find_similar,
get_pairings, get_license, activate_fonts, deactivate_fonts, tag_fonts, export_web,
render_preview, compare_preview, pick_fonts_for_brief, prepare_for_web, build_specimen

--- prompts/list: ['choose_fonts_for_brief', 'check_language_coverage']

--- resources/templates/list: ['font://{faceId}', 'collection://{id}', 'set://{id}']

--- tools/call search_fonts {"query":"serif","limit":2}
families: [ PT Serif (id 747, faces 747–750, ParaType Ltd, OFL, inactive) ], total 1
```

## 3. Grants

All four switches off (the default). Two mutating calls through the shim:

```
--- tools/call deactivate_fonts {"face_ids":[747]}
isError: true, code: permissionDenied
"AI assistants may not use deactivate_fonts yet. Turn on "Deactivate fonts" in
Settings → AI assistants to allow it."

--- tools/call tag_fonts {"face_ids":[747],"tags":["mcp-test"]}
isError: true, code: permissionDenied
"AI assistants may not use tag_fonts yet. Turn on "Tag fonts" in Settings → AI
assistants to allow it."
```

Nothing changed: PT Serif stayed inactive and untagged.

## 4. The deactivate_fonts confirmation

**Deactivate fonts** turned on, PT Serif Regular (face 747) activated for the session,
then `deactivate_fonts {"face_ids":[747]}` through the shim.

First call: the toast showed at the bottom of the app window (`confirm-toast.png`):

> An AI assistant wants to deactivate 1 font. No answer in 60 seconds counts as Deny.
> [Allow] [Deny]

No click within 60 s. The call returned after exactly 60 s:

```
isError: true, code: permissionDenied
detail: "tool deactivate_fonts was denied or timed out"
"The user did not allow deactivate_fonts. Nothing was changed."
```

Second call: **Allow** clicked after 13 s:

```
isError: false
{"outcomes":[{"face":747,"outcome":{"status":"done"}}]}
```

The face was deactivated.

## 5. Claude Desktop (Windows)

`claude_desktop_config.json` got the Claude Desktop snippet from Settings (the shim by
its absolute path, no token). Claude Desktop restarted. Screenshots:

- `claude-desktop-tools.png` — the tools list shows `font-manager`.
- `claude-desktop-brief.png` — the spec example: `pick_fonts_for_brief` for a bilingual
  Serbian (Cyrillic + Latin) / English brand, `render_preview` of
  "Београд / Beograd / Belgrade" in each candidate.
- `claude-desktop-refused.png` — `prepare_for_web` on the winner refused while
  **Activate fonts** and **Export web fonts** are off, with the Settings hint.
- `claude-desktop-prepared.png` — the same call after both switches are on: WOFF2 files
  and `fonts.css` written to `D:\private\fm-scratch\brand-web`.

macOS was not available for this test; the shim and the snippet are the same binary
and the same JSON on every OS (E27.7), and the Linux path is Claude Code over HTTP
(section 1).

## 6. What this test found

- Nothing to fix in the server, the shim or the grants.
- `docs/user/mcp.md` did not exist; it is written in this PR and linked from Settings →
  AI assistants and from Getting started.
- The help site's test assumed the page's `h1` id equals the file slug; for `mcp.md`
  (title "AI assistants") they differ, so the test now checks the title only.
